Is the agent healthy?

No runs match. Widen the window or clear filters. To create data run make agent-eval, or use the Run one ticket tool in the Evals tab.

Outcomes ⓘ

How runs ended: completed (answered), degraded (answered with a data source missing) or failed.

Runs over time ⓘ

Number of tickets processed per 10-minute bucket in the selected window, stacked by outcome. Gaps mean the agent was idle.

Latency per step ⓘp50 p95 p99

How long each stage of the pipeline takes. p50 is the typical run, p95/p99 the slow tail. The draft (LLM) step dominates; switch to log scale to see the others.

Cost by model ⓘ

Total model spend in the window, per model. “rules” is the deterministic drafter and is free; “untagged” are legacy runs written before model tagging.

Cost split ⓘ

Where the money goes: input vs output tokens, diagnosis vs customer reply text, and how much was spent on runs that succeeded vs failed.

Retries per run ⓘ

How many runs needed 0, 1, 2… retries against the upstream or the model. A growing tail means an unstable dependency.

Top events & errors ⓘ

Most frequent trace events (what happened inside runs) and error codes (why runs failed) in the window.

Data store

Where the run history is indexed. Files under runs/ are the source of truth; the index makes filtering fast.
